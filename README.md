# NotchDesk · 刘海桌面

![NotchDesk](branding/notchdesk-icon.png)

[官网与下载](https://dianming.site/notchdesk/) · [反馈问题](https://github.com/dianming-lab/NotchDesk/issues) · [MIT License](LICENSE)

把桌面，收进刘海里。原生 Swift / AppKit 开发，无第三方运行时依赖。

macOS 原生菜单栏小应用。鼠标靠近刘海两侧或下沿时展开桌面文件区，离开约 0.15 秒后完全隐藏，不显示灰色横条。隐藏时仍可感应鼠标或拖着文件靠近刘海。优先使用有刘海的屏幕；没有刘海时使用主屏幕顶部中央。

## 运行

从[官网](https://dianming.site/notchdesk/#download)下载安装包，或自行构建得到 `dist/NotchDesk.zip`。将 ZIP 复制到本机「下载」文件夹解压，再将 NotchDesk.app 拖到「应用程序」并双击打开。避免直接在 iCloud 同步目录内运行 .app，因为同步元数据可能影响本地签名验证。首次打开时，如果 macOS 询问是否允许访问桌面，请选择允许。应用不显示 Dock 图标，菜单栏里的托盘图标可以展开面板、打开桌面或退出。

也可以在项目目录执行：

```sh
zsh scripts/build.sh
open dist/NotchDesk.zip
```

需要 macOS 13 或更新版本和 Xcode Command Line Tools。本机构建为 Apple Silicon 应用，使用本地临时签名，尚未经过公证，不是正式发布版本。

## 使用

- 靠近刘海下沿或两侧，打开桌面文件列表；长列表可以滚动。
- 将列表里的文件拖到支持文件拖放的应用中（例如邮件附件区、聊天输入区、Finder）。默认采用复制语义，不移动桌面原件。
- 从 Finder 或支持文件拖放的应用拖文件靠近刘海，面板展开后松手，将其复制到桌面。
- 支持应用通过 File Promise 延迟提供的文件；仅有文字或网页链接的拖拽不会自动变成文件。
- 双击文件打开；右键文件可在 Finder 中定位。
- 同名文件自动添加 `(1)`、`(2)` 等编号，保留桌面已有文件和来源文件。
- 显示桌面顶层非隐藏文件及文件夹，不递归显示文件夹内部内容。不设置独立缓存副本，也不提供删除操作。
- 桌面变动通过目录监听更新，面板展开时每两秒补充检查一次。iCloud 桌面仍由系统管理，下载状态和同步速度取决于系统与网络。

如果桌面读取被拒绝：打开「系统设置 → 隐私与安全性 → 文件与文件夹」，允许 NotchDesk 访问桌面，重新启动应用。不需要辅助功能或屏幕录制权限。

## 验证

```sh
zsh scripts/test.sh
```

命令行测试无需 XCTest。安装完整 Xcode 后也可运行 `swift test`。

自动测试覆盖重名保留、原文件保留、桌面内重复拖入、文件夹复制、递归复制拒绝和不存在的来源。

人工验收建议：

1. 在桌面新建或重命名文件，确认列表更新。
2. 从 Finder 拖一个测试文件进刘海区域，确认桌面出现副本。
3. 再次拖入同名文件，确认原件内容不变且副本自动编号。
4. 从面板拖文件到一个 Finder 文件夹或支持附件的应用，确认接收成功。
5. 在另一个应用仍为前台时操作，确认面板不抢键盘焦点。
6. 检查全屏应用、多桌面、外接显示器，以及从 Photos / Mail 等应用拖出文件的表现；这些受来源应用的拖放协议影响，需要实机验收。

## 当前范围

这是可运行的第一版：尚未加入开机启动、文件筛选/固定、搜索、多选拖出、自动更新和正式签名发布。目录扫描在后台进行，展开时先显示已有列表。图标和列表视图仍在主线程加载，桌面文件特别多时仍有性能优化空间。


## 项目结构

- `Sources/NotchDesk/`：面板、桌面监听和文件复制逻辑。
- `Resources/`、`branding/`：应用图标及设计说明。
- `scripts/`、`Tests/`：构建和测试。
- `website/`：独立介绍页，可使用静态服务器预览。下载文件由发布流程另行放入。
